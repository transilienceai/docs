# Dashboards

## What it is

The **Dashboards tab** is a place to keep [outputs](outputs.md) you want to come back to often. When you "pin" an output, it appears on the Dashboards tab so you can reach it without digging through [run history](run-history.md).

Dashboards are organized by [app](apps.md) — outputs you pin from a given app are grouped together.

## Where to find it

The Dashboards tab is inside the main chat area, alongside the **Notifications** tab. It's not a top-level sidebar entry; you'll see it once you're on the home/chat view.

## How an output gets onto the Dashboards tab

From the [session detail](run-history.md#session-detail) **Files** tab, use the **pin to dashboard** action on any output. That output is now linked from the Dashboards tab. The file itself still lives with its original [session](sessions.md) — pinning just creates a quick-access reference.

To remove an output from the Dashboards tab, unpin it from the same place, or remove it from the tab itself.

## What you can do here

- **Quickly open** important outputs without searching run history.
- **Group** related outputs by app.
- **Unpin** outputs you no longer care about.

## How dashboards differ from artifacts

[Artifacts](artifacts.md) and dashboards both let you keep outputs around, but they serve different needs:

| | Dashboards | Artifacts |
|---|---|---|
| Organization | Flat, per-app | User-named folders |
| Use case | Quick access to current/important outputs | Long-term filing and saved collections |
| Multiple folders | No | Yes — create as many as you want |

If you just want one or two key outputs from an app close at hand, pin them to the Dashboards tab. If you're filing outputs into named collections (for example "Q1 Audit," "PCI Evidence"), use [artifacts](artifacts.md).

## Common questions

**"What is the Dashboards tab for?"** — Quick access to outputs you don't want to hunt for in run history.

**"How do I add something to it?"** — On the **Files** tab of a [session detail](run-history.md#session-detail), use the **pin to dashboard** action on any output.

**"How is this different from artifacts?"** — Dashboards is a flat per-app quick-access list. Artifacts are user-named folders for organized long-term storage. See the comparison table above.

**"Some apps produce a dashboard as an output — is that the same?"** — No. A dashboard *output file* is an interactive view inside one session (see [outputs](outputs.md#dashboards)). The **Dashboards tab** is a separate UI feature where you pin outputs across sessions.
